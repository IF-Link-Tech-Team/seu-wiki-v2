# 订阅画像共创测试

本提案提供用户画像的气泡式引导和本地订阅匹配实验，供共创成员体验、标注和评审。生产环境仍保留原有的订阅占位页，两个实验 API 在 `NODE_ENV=production` 时返回 404。正式开放需要另行确认产品规则、隐私说明和匹配质量。

## 两种体验方式

### 只体验画像

下载 [`prototypes/seu-profile-bubbles.html`](prototypes/seu-profile-bubbles.html)，在浏览器中打开。不需要安装依赖或运行服务器；脚本、样式和插画均在文件中，不请求网络。完成后可修改、重来或导出画像 JSON。该文件是独立演示，不会加载真实订阅消息。

### 在本地订阅页测试

按 [部署说明](deploy.md) 准备 Node.js 24、依赖、PostgreSQL 和环境变量。执行迁移后，使用仓库的开发命令分别启动 API 和网页：

```sh
npm ci
npm run db:migrate
npm run dev:api
# 在另一个终端运行
npm run dev:web
```

API 与网页均使用开发模式。保持采集、模型调用、飞书、IndexNow 等安全阀关闭；不需要启动 worker。生产模式的 Docker 站点不会开启本实验。

打开 `/subscription`：当前浏览器没有已保存画像时自动展示调查；保存后请求本地公开读取层返回订阅流。已经填写的用户可选择“修改订阅”或“重新体验新用户”。重新体验只移除画像，不删除反馈。

回放日期默认是 `2026-10-25`，可以在“测试方式与遗漏检查”中修改。只读取数据库已经发布、可见且符合公开条件的标题和摘要；空库不会显示真实消息。本提交不含抓取快照、生产数据库或任何测试者填写的数据。

## 画像与匹配

- 培养层次必填；学院和入学年份可留空。学院选择默认增加本学院信息关注；身份条件仍单独核对。
- 大气泡只展开，具体兴趣和明确的整组按钮才产生订阅。主题之间、关注机构之间使用 OR；选择整组时后端展开对应具体标签。
- 默认按兴趣或机构进入候选集；也可以选择接收兴趣之外的信息。明确不符合身份、已截止、命中排除类型的消息仍被过滤。
- 线下校区排除不影响明确的线上消息。地点或适用对象无法确定时进入“可能相关”，不会假定满足资格。
- 排序采用发布时间倒序，不采用综合分数阈值。每条结果可以查看标签证据、过滤理由并记录反馈。

规则仅基于标题和摘要，存在误标、漏标及资格识别不完整的问题，不能用作报名资格判定。订阅流同时包含“条件明确”和“可能相关”；评审时应抽查过滤记录，特别关注研究生专属信息、学院发布但跨院开放的信息、截止时间及线上线下混合场景。整组范围和原词表中的预留项可用范围也需要共同评审。

## 数据与实现

- 画像及反馈仅保存于当前浏览器；无账号同步、后台画像持久化或通知推送。加载订阅时通过 POST 把画像发给本地 API，避免放在 URL 中；响应 `private, no-store`。
- `industry/subscription-v2.ts`：v2 标签字典；`industry/subscription-onboarding.ts`：优化版兴趣分组。
- `packages/contracts/src/subscription*.ts`：画像、结果类型以及 HTML 与内部标签 ID 的转换。
- `apps/web/app/features/subscription/OptimizedOnboarding.tsx`：将优化版 HTML 放入仅允许脚本的隔离 iframe；消息校验窗口来源和随机会话标记，提交时校验标签。
- `apps/web/app/features/subscription/optimized-profile.html`：站内版界面与消息桥接；`docs/prototypes/seu-profile-bubbles.html`：可独立分发的原型。两者共享设计来源，但完成行为不同，修改交互时需同步核对。
- `packages/backend/src/publication/subscription*.ts`：公开数据读取、规则标注与匹配。单次最多核对 5000 条，达到上限时明确提示。
- 兼容此前的 v2 浏览器画像；旧版已选但优化界面没有列出的主题会补入“已保存的其他兴趣”。

## 验证

按照 CONTRIBUTING.md 执行类型检查、后端测试、网页构建、网页测试和启动后的冒烟检查。后端测试必须使用独立的 `*_test` 或 `*_ci` 数据库，先执行迁移。

```sh
npm run typecheck
npm test
npm run build -w @aihot/web
node --test apps/web/tests/*.test.ts
node scripts/smoke.ts --base http://localhost:3000
```

新增测试覆盖：标签转换、整组选择、旧画像兼容、身份冲突、类型与校区排除、线上消息、公开数据边界及生产入口关闭。人工流程核对：首次进入、已有画像回填、保存后订阅、刷新恢复、返回修改，以及 360/390 像素宽度下的气泡操作。

提交应经过仓库 CI（包括 Docker 冒烟）及至少一位维护者评审。本地测试通过不代表正式开放或匹配准确率已经达标。
