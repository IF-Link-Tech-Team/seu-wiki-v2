# 订阅数据与上线验收

订阅页面通过同源 `/api/site/subscription-preview` 请求消息，不传固定回放日期。
接口默认覆盖所有日期，并经 publication 读取层访问当前部署的 `DATABASE_URL`
所指数据库的 `publications` 和 `sources` 表。读取时按发布日期从新到旧分批匹配，
再对匹配结果分页。上海时区当天用于判断报名截止等条件。
响应为 `private, no-store`。进入订阅、点击刷新、切回窗口时重新请求数据。

生产 Compose 为 API 配置服务器数据库 `db:5432/aihot`，网页通过 `http://api:3001`
访问 API。功能上线需在 API 和 web 同时启用 `SUBSCRIPTION_EXPERIMENT_ENABLED=true`。
本机 `.env`、开发账号绕过、导入样本及本地数据库不得作为生产数据源提交。

页面的“消息范围”取自数据库中可用于订阅的最早和最新消息日期。
订阅读取已发布、可见且 eligible 的消息。新消息须先经过现有采集与发布流程。

部署验收：

1. 核对 API 连接的是正式站当前使用的数据库，再登录正式站完成画像，确认订阅显示全部日期。
2. 分别挑选一条近期和一条较早发布且符合该画像的消息，确认能在订阅中找到并打开。
3. 发布新的符合条件消息后，再次刷新订阅应出现该消息；撤回后再次刷新应消失。
4. 检查真实数据日期和接口错误，不能用本地样本测试替代正式站验收。

自动回归 `tests/subscription-publication.test.ts` 在独立数据库中验证新增发布和撤回能在
下一次请求生效，无需重启服务。真实服务器部署验收仍须在合并部署后执行。

## 登录与画像

订阅开关开启时，普通用户完成统一登录后进入本站 `/welcome`，弹窗显示画像调查。
已有画像会回填供确认，无画像的用户直接访问 `/subscription` 也会先进入此页面。
保存成功后回到 `/subscription`。这是 Wiki 的登录完成页，不是修改 Logto 或 Accounts 的登录页面。
后台和机构入口保留原回跳，关闭订阅开关时所有登录入口沿用原站内回跳。
欢迎页弹窗不能直接取消，订阅流中的“修改偏好”可以取消。
已有画像用户仍可直接访问订阅，弹窗是产品流程，不是新增的服务端访问权限。

画像继续存入 Wiki 数据库并关联 Accounts UUID，沿用现有会话、CSRF、Origin 和修订号校验。
本轮未新增画像表或修改统一账户服务。iframe 初始化增加握手重试，重复初始化不覆盖填写内容，
仅在服务器保存成功后进入订阅。此前用户反馈重新打开页面后恢复，原线上保存问题的具体原因未确认。

## 团队协作与验收边界

标签系统优化与 UI 优化需要其他成员同步推进，并共同验收：

- 标签维护成员继续校准分类归属、整组包含的标签、同义词和受众条件，用真实消息检查漏推与误推。
- UI/交互成员继续优化气泡选择提示、手机布局、键盘与辅助技术体验，以及插画资源加载。
- 双方修改标签 ID、分组或选择语义时同步更新调查选项、画像转换、匹配规则和回归样例，避免用户选择与结果不一致。

当前按全部公开历史逐批匹配，避免固定 30 天或 5000 条上限，但每次请求仍需遍历历史，
应随数据量增长评估性能。内嵌插画压缩后仍使订阅脚本超过 500 kB，构建有体积提示。
真实统一登录、跨浏览器画像恢复、正式库最新消息及移动端真实操作需团队环境验收。
本地自动化通过不代表这些验收完成，完成产品/隐私评审和登录链路验收前保持草稿。
